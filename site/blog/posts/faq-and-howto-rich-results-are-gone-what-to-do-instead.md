Google stopped showing HowTo rich results on 2023-09-13 and FAQ rich results for every site on 2026-05-07, so `FAQPage` and `HowTo` markup can no longer earn anything in Google Search. Existing markup is harmless and can stay. The useful move is to keep the visible questions and steps on the page, mark up the page's real subject instead, and use `QAPage` only for genuine community Q&A.

**Key takeaways**

- Don't add `FAQPage` or `HowTo` markup for Google anymore. No visual feature reads it.
- Don't rush to delete it either. Google says unused structured data does no harm.
- The visible content still matters: concise question-and-answer blocks and numbered steps are easy to quote as passages and in AI answers.
- Mark the page as what it is (`Article`, `Product`, `Service`, `LocalBusiness`) and add `VideoObject` with key moments if a tutorial has a video.
- `QAPage` is still active, but only for one question with user-submitted answers.

## What happened, in order

The FAQ and HowTo story played out over three years.

| Date | Change |
|---|---|
| August 2023 | FAQ rich results limited to well-known government and health sites. HowTo limited to desktop |
| 2023-09-13 | HowTo rich results removed on all devices |
| 2026-05-07 | FAQ rich results stopped appearing in Google Search for all sites |
| 2026-06-15 | FAQ structured data documentation removed |
| June to August 2026 | FAQ support removed from the Rich Results Test, Search Console reports and then the API |

The 2023 change was announced in Google's post on [changes to HowTo and FAQ rich results](https://developers.google.com/search/blog/2023/08/howto-faq-changes). The 2026 steps are recorded in the Search Central [documentation changelog](https://developers.google.com/search/updates), with a deprecation notice on 2026-05-08 and removal of the docs on 2026-06-15.

The practical result: the Rich Results Test no longer reports FAQ or HowTo items, and Search Console no longer has an enhancement report for them. If a plugin or old audit still reports "FAQ schema missing" as an error, that check is out of date.

## Should you remove existing FAQPage and HowTo markup?

Usually not, and never as an emergency. Use this decision table.

| Situation | What to do |
|---|---|
| Markup is accurate and generated by a template you aren't touching | Leave it |
| Markup contains answers that aren't visible on the page | Remove it or make the content visible. Hidden content in markup breaks Google's general guidelines |
| Markup duplicates or conflicts with another block | Clean it up during your next template change |
| A plugin adds FAQ markup to every page automatically | Turn it off. It bloats every page for no Google benefit |
| You're rebuilding the template anyway | Drop it and spend the effort on the page's main type |

Other parsers can still read `FAQPage` and `HowTo`, since they're ordinary schema.org types. If yours is accurate and costs nothing to maintain, keeping it is a defensible choice. Just don't report it to stakeholders as a ranking or click-through tactic.

## What to build instead

The rich result is gone, but the reasons people added FAQ and HowTo content are still valid. Readers have questions, and tutorials need steps. Shift the value from the markup to the visible page.

### 1. Keep a visible FAQ section that actually answers things

An on-page FAQ block still helps people, and it's a natural fit for passage-level results and AI answer engines. Write it so each answer stands alone:

- Put the question in a heading or bold line, worded the way people search.
- Answer in the first sentence, then add one or two lines of detail.
- Keep each answer under about 80 words unless the question truly needs more.
- Drop questions nobody asks. A FAQ padded with sales copy helps no one.

This kind of answer-first writing is the same pattern covered in [Generative Engine Optimization (GEO)](/blog/generative-engine-optimization-geo-how-to-get-cited-by-ai-search/). The point is the text, not a wrapper around it.

### 2. Mark up the page's real subject

A product page with a FAQ section is still a product page. A service page with questions at the bottom is still a service page. Put your structured data effort into the type that describes the main content:

- `Product` + `Offer` on pages that sell something.
- `Article` or `BlogPosting` on guides and tutorials.
- `LocalBusiness` subtypes on location pages.
- `Service` (no rich result, but clear entity markup) on service pages.

### 3. Turn tutorials into clean Articles with ordered steps

For a how-to guide, use `BlogPosting` or `Article` and write the steps as a real numbered list in the HTML (`<ol>`). Ordered lists are easy for any parser to read, and they can still surface as ordinary featured snippets.

```json
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "How to replace a bike chain in 6 steps",
  "description": "Tools, chain length and a step-by-step method for a 9- to 12-speed drivetrain.",
  "image": [
    "https://www.example.com/img/bike-chain-16x9.jpg",
    "https://www.example.com/img/bike-chain-4x3.jpg",
    "https://www.example.com/img/bike-chain-1x1.jpg"
  ],
  "datePublished": "2026-11-02T09:00:00-05:00",
  "dateModified": "2026-11-20T10:15:00-05:00",
  "author": {
    "@type": "Person",
    "name": "Sam Lee",
    "url": "https://www.example.com/authors/sam-lee/"
  }
}
```

Notice that the steps aren't in the markup at all. They live in the visible `<ol>`, which is what readers and crawlers actually consume.

### 4. Add video key moments if there's a video

If the tutorial has a video and the page is primarily about that video, `VideoObject` with `Clip` key moments is the closest living replacement for HowTo's step display. Each clip gets a name and a start time, and Google can link straight to that moment. Key moments only apply on watch pages where the video is the main content.

### 5. Use QAPage only for real community Q&A

`QAPage` is still an active rich result, but Google's [Q&A documentation](https://developers.google.com/search/docs/appearance/structured-data/qapage) is strict about where it applies: one question per page, with answers that users can submit. A site-written FAQ isn't eligible, and neither is a blog post that answers a question.

```json
{
  "@context": "https://schema.org",
  "@type": "QAPage",
  "mainEntity": {
    "@type": "Question",
    "name": "Why does my chain skip under load after a new cassette?",
    "text": "New cassette, same chain, and it skips on the three smallest cogs when I climb.",
    "answerCount": 2,
    "datePublished": "2026-11-10T08:12:00-05:00",
    "author": { "@type": "Person", "name": "trailrider42", "url": "https://forum.example.com/u/trailrider42/" },
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "A worn chain won't mesh with new cogs. Measure it with a chain checker and replace it if it reads 0.75% or more.",
      "datePublished": "2026-11-10T09:40:00-05:00",
      "upvoteCount": 14,
      "url": "https://forum.example.com/t/chain-skips/#answer-1",
      "author": { "@type": "Person", "name": "wrenchmonkey", "url": "https://forum.example.com/u/wrenchmonkey/" }
    },
    "suggestedAnswer": [
      {
        "@type": "Answer",
        "text": "Check the B-tension screw too. A new cassette can need a different setting.",
        "datePublished": "2026-11-10T11:02:00-05:00",
        "upvoteCount": 3,
        "url": "https://forum.example.com/t/chain-skips/#answer-2",
        "author": { "@type": "Person", "name": "commuterkat", "url": "https://forum.example.com/u/commuterkat/" }
      }
    ]
  }
}
```

The example is hypothetical. The required parts are the `Question` with `name`, `answerCount` and at least one `acceptedAnswer` or `suggestedAnswer`, and each `Answer` needs `text`. Everything in the markup must also be visible in the thread.

## Common mistakes after the deprecation

- **Converting a site FAQ into `QAPage` to keep the rich result.** It isn't eligible, and it misrepresents the page.
- **Deleting the visible FAQ along with the markup.** You lose the useful part and keep nothing.
- **Hiding FAQ answers in the markup only.** Content in JSON-LD that users can't see is a guideline violation for any type.
- **Leaving FAQ checks in your audit tooling.** If your reports still score `FAQPage` absence as a problem, retire that check so the team stops chasing it.
- **Selling FAQ markup as an AI tactic.** Google says there's no special schema needed for AI Overviews or AI Mode. If FAQ content helps there, it's the text doing the work.

It also checks that any FAQ answers in markup are visible on the page (`SCHEMA-003`) and that the page's main type has its required properties.
